# 03 — Database Schema

DB client: `lib/db/index.ts` — `drizzle(neon(process.env.DATABASE_URL!), { schema })`.
Schema source of truth: `lib/db/schema.ts`. Migrations live in `drizzle/` (SQL + meta snapshots), generated by drizzle-kit.

### `session` (Better Auth)

`id` PK, `token` UNIQUE, `user_id` FK → user (cascade), `ip_address`, `user_agent`, `expires_at` NOT NULL, timestamps.

### `account` (Better Auth OAuth accounts)

`id` PK, `account_id`, `provider_id`, `user_id` FK (cascade), `access_token`, `refresh_token`, `id_token`, `access_token_expires_at`, `refresh_token_expires_at`, `scope`, `password`, timestamps. Account linking is enabled so Google/GitHub same-email logins merge (see `lib/auth.ts`).

### `verification` (Better Auth)

`id` PK, `identifier`, `value`, `expires_at`, timestamps.

### `feedback` — public star ratings

`id` PK, `user_id` FK (cascade), `name`/`image` (denormalized snapshot), `stars` integer 1–5 NOT NULL, `comment` text NOT NULL, timestamps.

### `feature_requests`

`id` PK, `user_id` FK (cascade), `name`/`image`, `title` text NOT NULL, `description` text NOT NULL, `status` text NOT NULL default `'new'` (`'new' \| 'planned' \| 'shipped' \| 'declined'`), timestamps.

## Relations

`user → { sessions, accounts, aiSettings, interviewSessions, feedback, featureRequests }` (all `many`).
Each child table has a `one(user)` relation via its `user_id` FK.

## Query patterns

- Settings/sessions are looked up via `db.query.<table>.findFirst({ where: eq(...) })` using the drizzle relational API (schema object passed to `drizzle()` enables this).
- Leaderboard uses raw `sql` fragments with `count(*)::int`, `round(avg(score)::numeric, 1)`, `isNotNull(score)`, group-by user, ordered `avg desc nulls last, count desc`, limit 50.
- Completion counter uses `sql\`${user.mockInterviewsCompleted} + 1\`` guarded by `wasCompleted` so re-POSTs don't double-count.

## Notes / gotchas

- All FKs are `ON DELETE CASCADE` from `user`, so deleting a user cleans up settings, sessions, feedback, feature requests.
- Timestamps are `defaultNow()`; routes that update rows explicitly set `updatedAt: new Date()`.
- `feedback.name/image` are snapshotted at insert (from session user) — edits to the user profile do not backfill.
- There is no `applications`/`base_resume` table despite the PRD — resume/outreach data is intentionally ephemeral.
